# Plan: Modularize Code Indexing, Add .gitignore, Parallelism & Fix Symbol Extraction

## Problem Summary

1. **Monolithic**: `indexRepository()` in `incremental-indexer.js` is one big sequential function — scan, read, parse, store, build import graph, build call graph, compute complexity — all or nothing, no way to pause/resume or run phases independently.
2. **No .gitignore**: `scanner.js` uses hardcoded `IGNORE_DIRS_CODE` and dot-dir skipping. Project-specific `.gitignore` rules are ignored.
3. **No parallelism**: File reads are parallelized in batches of 50, but AST parsing and DB writes are sequential. Post-processing (import graph, call graph, complexity) runs sequentially.
4. **Incomplete symbols**: `parseFile()` re-reads files from disk even though content was already loaded, causing double I/O and potential inconsistency. Files that fail AST parsing silently return `[]`.

---

## Architecture: Current vs Proposed

### Current Flow (monolithic, sequential)
```
indexRepository()
  ├── scanRepository()          — synchronous recursive walk
  ├── for batch of 50 files:
  │     ├── readFileRecord()    — parallel I/O (good)
  │     ├── insertFile()        — sequential DB write
  │     ├── parseFile()         — RE-READS from disk (wasteful)
  │     └── insertSymbol()      — sequential DB write per symbol
  ├── buildImportGraph()        — loads ALL files, regex extraction, N+1 queries
  ├── buildCallGraph()          — loads ALL symbols, RE-PARSES all files via AST
  └── buildComplexity()         — loads ALL symbols
```

### Proposed Flow (pipelined, parallel)
```
Phase 1: SCAN
  scanRepository()  — respects .gitignore, returns file list

Phase 2: PARSE + STORE  (worker threads for AST)
  ├── readFileRecord()        — parallel I/O
  ├── parseContent()          — NEW: accepts content string, no disk re-read
  ├── insertFile()            — batched INSERT (transaction per batch)
  └── insertSymbol()          — batched INSERT (transaction per batch)

Phase 3: DERIVED INDEXES  (parallel)
  ├── buildImportGraph()      — optimized batch resolution
  ├── buildCallGraph()        — uses stored content, no re-read
  └── buildComplexity()       — independent, can run concurrently
```

```javascript
// Phase 3: Derived Indexes (import graph, call graph, complexity)

    buildImportEdges(db, repoId),
    buildCallEdges(db, repoId),
```

**Key changes**:
- Each phase is independently callable and resumable
- `reindexRepository()` can skip phases when not needed
- Store intermediate state (scanned file list, parse progress) in `code_repos` metadata or a temp table
- Backward compatible — existing callers still work

### 2. Add .gitignore Support

**Files**: `src/code-index/scanner.js`, `utils.js`

Add `.gitignore` parsing using the [`ignore`](https://www.npmjs.com/package/ignore) npm package (lightweight, well-maintained):

```javascript
// scanner.js
const ignore = require('ignore');

function loadGitignore(repoPath) {
  const ig = ignore();
  // Walk up from repoPath, load .gitignore at each level
  // (most specific last, so it wins)
  const gitignorePath = path.join(repoPath, '.gitignore');
  if (fs.existsSync(gitignorePath)) {
    ig.add(fs.readFileSync(gitignorePath, 'utf-8'));
  }
  return ig;
}

function scanRepository(repoPath, options = {}) {
  const ig = loadGitignore(repoPath);
  const results = [];

  function walk(dir) {
    const entries = fs.readdirSync(dir, { withFileTypes: true });
    for (const entry of entries) {
      const fullPath = path.join(dir, entry.name);
      const relativePath = path.relative(repoPath, fullPath);

      if (entry.isDirectory()) {
        if (shouldSkipDir(entry.name, extraIgnoreDirs)) continue;
        if (ig.ignores(relativePath)) continue;
        walk(fullPath);
      } else if (entry.isFile() && isCodeFile(fullPath)) {
        if (ig.ignores(relativePath)) continue;
        results.push(fullPath);
      }
    }
  }

  walk(repoPath);
  return results;
}
```

**Add dependency**: `npm install ignore` (~15KB, zero deps)

**Edge cases**:
- No `.gitignore` found → fall back to current hardcoded behavior
- Nested `.gitignore` files → chain them (most specific wins)
- `.gitignore` patterns like `*.min.js`, `generated/**`, `vendor/` all handled

#### 3b. Batch DB writes with transactions

**File**: `src/code-index/repos.js`, `src/code-index/incremental-indexer.js`

Wrap batch inserts in transactions:

```javascript
// repos.js — add batch methods
function insertFileBatch(repository, repoId, records) {
  db.prepare('BEGIN').run();
  try {
    const ids = records.map(r => repository.insertFile(r));
    db.prepare('COMMIT').run();
    return ids;
  } catch (e) {
    db.prepare('ROLLBACK').run();
    throw e;
  }
}

function insertSymbolBatch(repository, symbols) {
  db.prepare('BEGIN').run();
  try {
    for (const sym of symbols) repository.insertSymbol(sym);
    db.prepare('COMMIT').run();
  } catch (e) {
    db.prepare('ROLLBACK').run();
    throw e;
  }
}
```

In `incremental-indexer.js`, accumulate symbols per batch and do one transaction:

```javascript
// Inside the batch loop
```

### 4. Fix Incomplete Symbol Outlines

#### 4a. Root cause analysis

The incomplete outlines stem from multiple issues:

1. **Double disk read**: `parseFile()` re-reads from disk even though content is already in memory. If the file is locked, modified, or has encoding issues, the second read fails silently → empty symbols.

2. **Silent failures**: `parseFile()` catches all errors and returns `[]`. No logging or tracking of parse failures.

3. **Call graph re-parses files**: `buildCallGraph()` calls `extractCallees()` which reads each file from disk again (3rd read of the same file). If the file was deleted or changed between index and post-processing, callees are lost.

4. **No content validation**: Files with syntax errors produce empty parse trees. No fallback.

#### 4b. Fixes

**Fix 1**: Use `parseContent()` everywhere (from 3a above) — eliminates double reads.

**Fix 2**: Store content in `code_files` (already done!) and use it for call graph building instead of re-reading from disk.

```javascript
// legacy-core.js — buildCallGraph modification
// Instead of: codeParser.extractCallees(filePath)
// Use: codeParser.extractCalleesFromContent(filePath, symbol.file_content)
const callees = codeParser.extractCalleesFromContent(symbol.file_path, symbol.file_content);
```

**Fix 3**: Add parse failure tracking and logging:

```javascript
// incremental-indexer.js
if (symbols.length === 0 && record.content.trim().length > 0) {
  const hasExports = /\bexport\s/.test(record.content);
  const hasFunction = /\bfunction\s|\b=>\s|def\s|func\s|fn\s/.test(record.content);
```

**Fix 4**: Add a lightweight regex fallback parser for when tree-sitter fails:

```javascript
// parse-code.js — fallback when AST returns empty
function fallbackExtractSymbols(filePath, content) {
  const symbols = [];
  const ext = path.extname(filePath);

  if (['.js', '.mjs', '.cjs', '.ts', '.mts', '.cts', '.tsx'].includes(ext)) {
    // Match exported functions, classes, const
    const re = /export\s+(?:default\s+)?(?:function|class|const|let|var)\s+(\w+)/g;
    let match;
    while ((match = re.exec(content)) !== null) {
      symbols.push({
        name: match[1],
        kind: match[0].includes('function') ? 'function' : match[0].includes('class') ? 'class' : 'constant',
        language: ext === '.tsx' ? 'typescript' : ext.slice(1),
        file: filePath,
        signature: match[0],
        qualified_name: match[1],
        start_line: content.substring(0, match.index).split('\n').length,
        end_line: content.substring(0, match.index).split('\n').length,
        start_byte: match.index,
        end_byte: match.index + match[0].length,
        docstring: '',
        body_preview: '',
        parent_name: '',
      });
    }
  }
  // Similar for Python, Go, Rust...

  return symbols;
}

function parseContent(filePath, content) {
  // ... existing AST logic ...
  const symbols = /* AST extraction */;
  if (symbols.length === 0 && content.trim().length > 0) {
    return fallbackExtractSymbols(filePath, content);
  }
  return symbols;
}
```

## Decisions (confirmed)

- **.gitignore**: Use `ignore` npm package (lightweight, zero deps, handles all gitignore edge cases)
- **Parallelism**: In-process optimizations first (batch transactions, parallel post-processing, eliminate double reads). Worker threads deferred to future benchmark-driven effort.
- **Fallback parser**: Yes, add regex fallback as safety net when AST returns empty

---

## Risks & Mitigations

- **SQLite write contention**: Parallel writes to SQLite are serialized by WAL locks. Mitigation: batch writes in transactions, do CPU work (parsing) in parallel, write sequentially.
- **Fallback parser false positives**: Regex fallback may extract "symbols" from comments or strings. Mitigation: only use fallback when AST returns empty AND file has recognizable patterns.
- **Backward compatibility**: All changes maintain the existing `indexRepository()` / `reindexRepository()` API. New phase functions are additive.
