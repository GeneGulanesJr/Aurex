### Dead Code

1. **`packages/backend/src/migrations/`** — 5 SQL migration files. Nothing in the source code references them. The build script copies them to dist (`cp -r src/migrations dist/migrations`) but no runtime code uses them. Spec says "LaPis manages its own schema". These are leftovers from the old `migrator.ts` which was removed.

2. **`packages/shared/src/api.ts`** — Duplicates interfaces from `rest.ts` with different shapes, has unused imports, not exported from barrel. Dead code.

3. **`packages/frontend/src/websocket.ts`** — `MissionWebSocket` class is defined but never imported or used by any component. App.tsx uses `useWebSocket` hook instead. The class connects to `/ws/${missionId}` but the backend WS route is at `/ws` (no parameter), so this class would 404 if used.

### Dead Config

4. **`wsPort` in config.ts** — Config loads `WS_PORT` (default 3001) but it's never used. WebSocket is served on the same Fastify instance as REST (port 3000). The docker-compose.yml exposes port 3001 but nothing listens on it. The frontend nginx.conf proxies `/ws/` to `backend:3000` (not 3001).

### Security

5. **Shell injection in `worktree.ts`** — The `git()` function interpolates parameters directly into shell commands: `git -C ${repoRoot} branch ${taskBranch}`. Branch names like `task/worker-a/feature; rm -rf /` would execute arbitrary commands. Should use `execFile` with argument arrays or sanitize inputs.

### Missing Spec Features

6. **WS client→server messages not handled** — Spec §6b defines `subscribe_mission` and `checkpoint_decision` as client→server WS messages. The backend WS handler only supports `auth` and `replay` messages. The spec says "REST is primary. WS is for low-latency when user is already in modal." The REST checkpoint path works, but the WS shortcut is missing.

## Issues to Fix

### Critical (Spec Violations)

1. **Frontend anime.js not wired to components**: The animation modules exist but are not actually used by the React components. `AgentNode`, `CostCounter`, `MilestoneBar`, `StatusFeed`, and `EscalationOverlay` all use CSS transitions or static rendering instead of the anime.js functions defined in `src/animations/`. Spec §5e explicitly requires these animations.

### Security

2. **Shell injection in `worktree.ts`**: The `git()` helper interpolates unsanitized parameters (branch names, paths) directly into shell command strings via template literals (`git -C ${repoRoot} branch ${taskBranch}`). Malicious branch names could execute arbitrary commands. Fix: use `child_process.execFile` with argument arrays.

### Cleanup (Spec §4d / Dead Code)

3. **`better-sqlite3` and `@types/better-sqlite3` still in `package.json`**: Not imported anywhere. Spec §4d explicitly says "No more better-sqlite3 dependency — removed from backend."

4. **`uuid` and `@types/uuid` still in `package.json`**: Not imported anywhere. Dead dependency.

5. **`@fastify/cors` and `@fastify/rate-limit` in `package.json`**: Not imported anywhere. Either remove or wire up.

6. **`packages/backend/src/migrations/` directory**: 5 SQL files never referenced by any runtime code. Build script copies them to dist but nothing uses them. Spec says "LaPis manages its own schema." Leftover from removed `migrator.ts`.

7. **Orphaned `packages/shared/src/api.ts`**: Dead code with duplicate interface names that differ from `rest.ts`. Should be removed.

8. **Dead `packages/frontend/src/websocket.ts`**: `MissionWebSocket` class is never imported by any component. It also connects to `/ws/${missionId}` but the backend route is `/ws` (no parameter) — would 404 if used.

9. **Dead `wsPort` config**: `loadConfig()` reads `WS_PORT` but the value is never used. WS is served on the same Fastify instance as REST (port 3000). Docker-compose exposes 3001 but nothing listens on it.

### Missing Spec Features

10. **WS `subscribe_mission` / `checkpoint_decision` not handled**: Spec §6b defines client→server WS messages. Backend only supports `auth` and `replay`. REST checkpoint path works, but WS shortcut for low-latency decisions is missing.

### Minor (Deviations from Spec)

11. **WorkerStatus has extra `"planned"` value**: Not in spec §9a but used by milestone-loop retry logic to reset units. Harmless extension.

12. **CheckpointTrigger has extra `"cost_cap_exceeded"` value**: Not in original spec but enables cost cap enforcement from §7d. Good extension that should be documented in spec.

13. **WsClientEvent has extra `mission_queued`/`mission_completed` types**: Needed by the mission pool pattern. Spec assumed single-mission. Reasonable extensions.

14. **LaPis `runCompression` actually calls API instead of being stubbed**: Spec said "stubbed — logs skip, never silent" but implementation POSTs to LaPis. Arguably better behavior.

15. **EscalationContext.trigger uses inline literal instead of CheckpointTrigger**: Spec §5c uses `CheckpointTrigger` type but implementation uses a narrower inline union. Functionally equivalent.

### Design Improvements (Beyond Spec)

16. **Mission Runner Pool**: Extends spec's single-mission runner to support concurrent missions with queueing. Significant and valuable extension.

17. **Auth middleware**: Optional API key authentication on REST and WS endpoints. Essential for deployment.

18. **Mission abort endpoint**: `POST /api/missions/:id/abort` for frontend sidebar.

19. **Active missions endpoint**: `GET /api/missions/active` for multi-mission sidebar.

**Overall Assessment**: The implementation faithfully follows both specs (restructuring + orchestrator runtime + worker spawning). The backend is comprehensive and well-tested with 193 passing tests. The primary functional gap is in the frontend where anime.js animation functions exist as modules but are not integrated into the React components. There is technical debt from the migration: `better-sqlite3`, `uuid`, CORS, and rate-limit dependencies are still in `package.json` despite never being imported (spec §4d explicitly required removing better-sqlite3). The migration SQL files are similarly leftover. A shell injection vulnerability exists in `worktree.ts` where branch names are interpolated into git shell commands without sanitization. The implementation adds several useful extensions beyond spec (multi-mission pool, auth, abort) that should be documented back into the spec.
