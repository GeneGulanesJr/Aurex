# Aurex — Implemented-but-Not-Connected Review & Remediation Plan

> Review of the Aurex monorepo for features that are **implemented but not wired up properly**
> (dead code, broken plumbing, contract mismatches, discarded results, half-wired lifecycles,
> components built but never mounted). Findings are verified against current code with `file:line`
> evidence. Each is tagged **[ACCIDENTAL]** (a real bug/gap) or **[SCAFFOLDING]** (intentional,
> off-by-default feature flag — noted for completeness, lower priority).

## Methodology

Four parallel read-only audits covered: (1) backend client/orchestrator wiring, (2) route
registration + REST/frontend contract drift, (3) frontend component/hook mounting, (4) the durable
queue / prepared-sessions / reconciler subsystem. Full `file:line` evidence was gathered; items
explicitly checked and found *fine* are listed in §6.

## §1. Findings — ACCIDENTAL gaps (worth fixing)

### BLOCKER

**A1. Mutation testing UI is built but never mounted — feature is unreachable**
- `packages/frontend/src/active/MutationPanel.tsx:11` has **zero importers** (only self + a doc
  comment in `active/mutation-score.ts:2`). `IntegrationsPanel.tsx:19-23,68-136` renders only
  GitHub + PiNyx tabs — **no mutation tab**. README advertises "Mutation testing" as part of the
  Integrations Panel (`README.md:48,67`).
- Backend routes are fine (`mutation-routes.ts:47,56,120`). Pure frontend wiring gap.
- **Fix:** Add a "Mutation testing" tab/section to `IntegrationsPanel` (or a sub-view of
  `RepoOverviewPanel`) that mounts `MutationPanel` for the selected repo.

### HIGH

**A2. Quota gate is bypassed on the highest-token path (worker/validator/researcher model calls)**
- The quota wrapper is real and enforced **only** on orchestrator-direct calls
  (`mission-runner.ts:64-80` → planner/milestone/checkpoint loops). But agent workers — which do
  the actual coding and consume the most tokens — build their **own** Pi SDK `ModelRegistry` pointed
  straight at PiNyx (`agent-spawner.ts:777-831`), bypassing the quota-wrapped client entirely.
- README:69 claims "Rate-limit per coding plan via `pinyx-quota-wrapper`." Coverage is partial.
- **Fix:** Thread the quota-wrapped `PinyxClient` (or the quota pre-flight check) into the spawner's
  model-resolution path so agent calls pass through the gate.

**A3. Broadcast subsystem is fully unconnected**
- `writeBroadcast` / `transitionBroadcast` / `getBroadcasts` (`lapis-client.ts:104-106,398-407`)
  have **zero callers** anywhere — no agent tool, no route, no orchestrator. Broadcasts can never be
  created, read, or advanced.
- `enforcement/broadcast-lifecycle.ts` + `enforcement/enforcement-gate.ts`'s
  `enforceBroadcastTransition` are likewise dead (no callers).
- **Fix:** Either expose a broadcast tool to agents + a read route for the dashboard, **or** delete
  the dead client/enforcement code if the feature was dropped. (Needs a product decision — see §5.)

### MEDIUM

**A4. Research-finding lifecycle is half-wired (findings never advance past `unverified`)**
- `writeFinding` (`research-tools.ts:48`) and `getFindings` (`milestone-loop.ts:129,212`;
  `checkpoint-loop.ts:98`) are used, but `transitionFinding` (`lapis-client.ts:110,414`) has **zero
  callers**. `enforcement/research-lifecycle.ts` + `enforcement-gate.ts`'s
  `enforceResearchTransition` are dead.
- **Fix:** Call `transitionFinding` (verified/superseded/expired) from the milestone/negotiator path
  after findings are consumed or superseded; or delete the dead transition + lifecycle code.

**A5. Checkpoint route ignores its `:id` (missionId) path param — no mission scoping/ownership**
- `routes/checkpoints.ts:21-37` registers `POST /api/missions/:id/checkpoints` but never reads
  `request.params.id`; it resolves purely off `body.checkpointId`. The mission id is decorative — an
  IDOR surface and misleading API shape.
- **Fix:** Read the path param, verify the checkpoint belongs to that mission (and the caller), and
  404/403 on mismatch.

**A6. `useQuota` real-time WebSocket subscription is dead code**
- `hooks/useQuota.ts:32-52` has a WS branch gated on `if (wsUrl)`, but every caller passes no arg
  (`App.tsx:75`, `QuotaPanel.tsx:35`) → WS branch never runs. Backend emits `quota_update` /
  `quota_exhausted` (`shared/events.ts:124,131`; broadcast unfiltered at `ws/events.ts:174-183`),
  yet the QuotaPanel/TopBar quota dot only refresh on the 30s poll (`useQuota.ts:30`).
- **Fix:** Pass the WS URL (or wire the shared ws connection) into `useQuota` so it subscribes, or
  remove the dead branch.

**A7. Post-commit / symbol-level overlap detection is never run**
- `overlap.ts`: `detectOverlap` (`:105`) and `computePostCommitScope` (`:91`) have **zero callers**.
  Only `checkPreSpawnOverlap` (`:59`) is used (`milestone-loop.ts:257`). Overlap is purely
  pre-spawn declared-path/module string matching; `getCodeGraph`/`getCodeHotspots` are not wired in.
- **Fix:** Invoke `computePostCommitScope`/`detectOverlap` after a worker commits (milestone-loop
  post-commit hook) using the code graph, **or** delete the unused functions.

**A8. Rescope never supersedes the contract (inconsistent append-only invariant)**
- `rescope.ts:131` only calls `createWorkingUnit`. Neither the auto-rescope
  (`milestone-loop.ts:925`) nor user rescope (`checkpoint-loop.ts:104`) calls `supersedeContract`.
  Yet `planner.ts:398-409` *does* supersede on re-creation, and `planner.ts:385-387` documents
  contracts as append-only. So the invariant holds on planning but is skipped on rescope → incomplete
  contract audit trail (tracked as gap #8876).
- **Fix:** Call `supersedeContract` in the rescope path before creating the new working unit.

**A9. Missing `agent_session_*` WebSocket lifecycle events (within intended first-PR scope)**
- Only **2** of ~11 planned durable events exist: `execution_job_claimed` (`events.ts:133-138`) and
  `stale_reconciliation_completed` (`:139`). All `agent_session_prepared/queued/started/heartbeat/
  completed/failed/lost` events are undefined and never emitted (plan Task 1 Step 3, first-PR scope).
- **Fix:** Define the `agent_session_*` event variants in `shared/events.ts` and emit them from
  `prepared-session-service.ts` on each lifecycle transition.

**A10. Bumblebee exposure-catalog feature has no UI (3 dead API functions)**
- `getExposureCatalog` (`api.ts:432`), `saveExposureCatalog` (`:438`), `getBumblebeeStatus`
  (`:401`) have no non-test importer. Backend routes exist (`bumblebee.ts:15,48,53`). Supply-chain
  *scan* UI works; catalog management / scanner-health UI is unbuilt.
- **Fix:** Add a catalog/health sub-panel to the Supply Chain area, **or** drop the client fns.

### LOW

**A11. Orphaned `api.ts` client functions (backend routes exist, no UI caller)**
- `getCurrentMission` (`api.ts:52`), `saveGitHubConfig` (`:144`), `getRepoSummary` (`:357`),
  `triggerRepoScan` (`:381`), `getScanResults` (`:426`). Mostly dead UI wiring; some imply a missing
  UI affordance (e.g. no way to trigger a *repo-level* scan from the UI — only mission-level scans).
- **Fix:** Wire the genuinely useful ones (repo-level scan trigger) or delete the rest.

**A12. Dead enforcement / guard helper modules (redundant, real enforcement done elsewhere)**
- `enforcement/branch-guard.ts` `isBranchAllowed`/`validateCommitBranch` — zero callers; real branch
  enforcement is the inline git pre-commit hook written by `worktree.ts:184-216`.
- `enforcement/contract-immutability.ts` `validateContractAppend`/`validateSupersede` — zero callers
  (`planner.ts:5` documents the skip as intentional; invariant may be enforced LaPis-side).
- `enforcement/quota-gate.ts` `getQuotaStatusDisplay` (`:143`) + `prefire` (`:61`) — unused helpers.
- **Fix:** Delete redundant dead code, or wire it where intended.

**A13. Doc drift (api.md)**
- Auth model mismatch: docs say `API_KEY` Bearer (`docs/api.md:7`); code does Auth0 JWT
  (`routes/auth.ts:30-66`).
- Stale `Source:` line refs for `missions.ts` (off by ~47-65 lines), wrong mutation-status path
  (`:223` says `/mutation/run/:runId`, real is `/mutation/:runId`), mangled anchor (`:28`),
  checkpoint body/response shape (`:99-102`), and `/health` undocumented.
- **Fix:** Reconcile docs with code in one cleanup pass.

## §2. Findings — SCAFFOLDING (intentional, flags off by default — context only)

These are deliberately behind off-by-default flags per the durable-queue plan cutline
(`docs/superpowers/plans/2026-06-11-prepared-sessions-durable-queue.md:319-344`). Listed so the team
knows the *real/stub boundary*, not as bugs to chase now:

- **`agent_session_start` handler is a guaranteed-fail stub** (`prepared-session-service.ts:123-128`)
  — by design, no agent is spawned yet.
- **`mission_start` is never enqueued**; `POST /api/missions` uses the synchronous `pool.submit`
  path (`missions.ts:164,246`). Durable mission dispatch is unwired (deferred per plan).
- **`durable-mission-runner.ts` was never created** (the `mission_start`→runner adapter).
- **Heartbeat store methods implemented but never called** (`execution-queue-store.ts:206,328`;
  `prepared-session-store.ts:218,308`); no `session-heartbeat.ts`/`session-recovery.ts` exist.
- **Stale reconciler is manual-only** (`POST /api/execution-queue/reconcile`); no periodic timer.
- **`agentSessionRoutes`/`executionQueueRoutes` registered only when flags on** (`server.ts:224-236`)
  → documented durable endpoints 404 on a default install (`docs/api.md:28,301-358`).
