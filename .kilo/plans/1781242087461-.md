# PR #93 Review: Persistent Data Volumes + In-App Self-Update System

**Verdict: Good to merge with minor fixes**

Well-structured PR with clean separation of concerns. The flag-file + cron approach for VPS safety is sound. Auth will be addressed in a separate PR so it's excluded from this review. A few correctness/UX issues remain.

## Worth Noting

### 1. `/aurex` mount changed from `ro` to read-write (`docker-compose.yml:52`)
This is required for the `.update-pending` flag file, but it means the backend container can now write to the entire project source tree. Acceptable for now since the backend is trusted code, but worth being aware of.

## Issues to Fix

### 2. `behindBy` can be 0 when SHAs differ (`packages/backend/src/routes/update.ts:72-76`)
When `localHead !== latestSha`, the code runs `git log --oneline ...` which can fail (e.g., shallow clone, network issues). On failure it catches to `""`, making `logCount.split("\n").filter(Boolean).length === 0`. So the UI shows "0 commits behind" but also shows an UPDATE button. This is confusing.

**Fix:** Set `behindBy` to at least 1 when `localHead !== latestSha`, even if the log fails:
```ts
behindBy = logCount ? logCount.split("\n").filter(Boolean).length : 1;
```

### 3. `setTimeout` for daily scheduling is unreliable (`packages/backend/src/routes/update.ts:101-113`)
`setTimeout` with multi-hour delays can be lost if the Node process is under memory pressure, or if the event loop is blocked for extended periods. Long `setTimeout` values are also not preserved across process restarts.

**Fix:** Consider using `setInterval` with a short interval (e.g., every 5 minutes) and checking the time:
```ts
setInterval(() => {
  const now = new Date();
  if (now.getHours() === 8 && now.getMinutes() === 0 && now.getSeconds() < 300) {
    checkForUpdates();
  }
}, 5 * 60 * 1000);
```
Or use a proper cron library like `node-cron` if one is already available.

### 4. Race condition in `apply` callback (`packages/frontend/src/hooks/useUpdateStatus.ts:55-71`)
The `apply` function reads `applying` from the closure, but `setApplying(true)` is asynchronous in React. If the button is double-clicked quickly, both invocations see `applying === false`.

**Fix:** Use a ref for the applying guard:
```ts
const applyingRef = useRef(false);
const apply = useCallback(async () => {
  if (applyingRef.current) return;
  applyingRef.current = true;
  setApplying(true);
  // ...
}, []);
```

### 5. `fetch("/health")` may not resolve in production (`packages/frontend/src/hooks/useUpdateStatus.ts:62`)
In development, the Vite proxy forwards `/health` to `localhost:3000`. But in production, the frontend is built and served from Docker. The `/health` endpoint needs to be reachable from the browser. If there's no reverse proxy routing `/health` to the backend, this polling will 404 and the UI will be stuck in "UPDATING..." forever.

**Fix:** Use the same `apiFetch` helper (which knows the backend URL) instead of raw `fetch("/health")`, or ensure the production proxy config routes `/health` correctly.

## Minor Issues

### 6. Empty catch in `checkNow` (`packages/frontend/src/hooks/useUpdateStatus.ts:51-54`)
Already flagged by the bot review. At minimum, log to console for debuggability:
```ts
} catch (err) {
  console.warn("[update] Manual check failed:", err);
}
```

### 7. Hardcoded `main` in `cron-update.sh:31` 
Already flagged. The backend uses `config.gitMainBranch` but the cron script hardcodes `main`. If the default branch ever changes, these will desync. At minimum add a comment; ideally read from a config file.

### 8. No rollback mechanism in `cron-update.sh`
If `git pull` succeeds but `docker compose up --build -d` fails, the system is in a broken state with no way to auto-recover. Consider:
- Stashing the pre-pull SHA
- Adding a rollback step if the build fails: `git checkout $PREV_SHA && docker compose up --build -d`

### 9. `lapis-data` volume mounts to `/root/.pi` (`docker-compose.yml:8`)
Minor: the volume name is `lapis-data` but it mounts to `/root/.pi`. The name is fine, but worth a comment in the compose file for clarity about what data lives there.

- **30-second timeout on git operations** — prevents hanging
- **`flock` concurrency protection in cron script** — prevents double-rebuilds
- **WebSocket push + REST fallback** — good UX pattern for update notifications
- **Clean shared types** — `UpdateStatusResponse` properly shared between frontend/backend
- **Animation CSS** — tasteful pulsing dot, not distracting
- **`captureBuildSha()` fire-and-forget** — correctly handles async init without blocking startup
