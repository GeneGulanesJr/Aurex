# Dummy Implementation Review — Aurex Codebase

## Summary

Reviewed all 50+ source files across `packages/backend`, `packages/frontend`, and `packages/shared`. Found **8 notable dummy/stub implementations** categorized below by severity.

## HIGH — Genuine stubs / incomplete implementations

### 1. `runCompression` — explicitly marked "(stubbed)"
- **File:** `packages/backend/src/clients/lapis-client.ts:71`
- **Function:** `LaPisClient.runCompression`
- **Detail:** The interface declaration has comment `// State compression (stubbed)`. The implementation at line 258 delegates a POST to `/missions/${missionId}/compress`, but the "(stubbed)" label signals the developer considers this incomplete or the backend endpoint itself not yet real.

### 2. `onEscalation` callback — empty no-op body
- **File:** `packages/backend/src/orchestrator/mission-runner.ts:96-99`
- **Function:** `onEscalation` callback passed to `createMilestoneLoop`
- **Detail:** All 3 parameters are unused (prefixed `_`). The body is empty with a comment saying "Loop no longer emits escalation events directly." However, `milestone-loop.ts` calls this callback at **5 separate locations** (lines 193, 322, 362, 381, 386-390). All 5 calls are silently discarded. Escalation is handled via the loop's return value and checkpoint mechanism instead, making this callback vestigial.

### 3. `installBranchGuard` — ignores all parameters
- **File:** `packages/backend/src/orchestrator/worktree.ts:57-81`
- **Function:** `WorktreeManager.installBranchGuard`
- **Detail:**
  - `_worktreePath` is completely ignored — the hook is installed in `repoRoot/.git/hooks` regardless of which worktree is specified
  - `_allowedBranch` is completely ignored — branch patterns are hardcoded to `task/*`, `integration/*`, `release/*`
  - Empty `catch {}` block at line 79 silently swallows all errors (permission failures, disk errors, etc.)
  - The interface signature at line 14 accepts `worktreePath` and `allowedBranch` but the implementation uses neither

## MEDIUM — Hardcoded placeholders / fallback data

### 4. `STUB_MODEL` constant — fallback for all agent roles
- **File:** `packages/backend/src/routes/missions.ts:36` and `packages/backend/src/routes/pinyx.ts:61`
- **Function:** `resolveDefaultModel` and model hint defaults
- **Detail:** The constant `"kilo/kilo-auto/free"` is explicitly named `STUB_MODEL`. Used as the default for all 5 agent model roles (`orchestrator`, `worker`, `validator_scrutiny`, `validator_user_testing`, `research`) when no real model is configured. The code actively tries to discover real models via `resolveDefaultModel()`, but if discovery fails, all roles fall back to this stub.

### 5. `WorkingUnit` created with empty placeholder fields from WS events
- **File:** `packages/frontend/src/hooks/useMission.ts:58-62`
- **Function:** `missionReducer` (`AGENT_STATUS` case)
- **Detail:** When a new agent is discovered via WebSocket `agent_status` event, the reducer creates a `WorkingUnit` with hardcoded empty values:
  - `declaredPaths: []`, `declaredModules: []`, `taskBranch: ""`, `worktreePath: ""`, `sessionId: ""`
  - `description: "${agentType} agent"` — auto-generated rather than from real data

### 6. `entries: 0` hardcoded in cost update
- **File:** `packages/frontend/src/hooks/useMission.ts:38`
- **Function:** `missionReducer` (`COST_UPDATE` case)
- **Detail:** The `CostSummary.entries` field is hardcoded to `0` rather than being derived from the WebSocket event data. The `cost_update` event provides `totalCost` and `totalTokens` but not `entries`.

## LOW — Minor / intentional design choices

### 7. `createIdle` — minimal implementation (no animation)
- **File:** `packages/frontend/src/animations/agent-animations.ts:25-27`
- **Function:** `createIdle(element)`
- **Detail:** Unlike the other animation functions (`createPulse`, `createSpin`) which return anime.js instances, `createIdle` only sets `element.style.opacity = "0.5"` — a single CSS property assignment with no animation. Per DESIGN.md, idle should be "a slow breathing opacity animation" but there's no anime.js animation loop. This is inconsistent with the design spec.

### 8. `createSpin` — silently returns `undefined` when no `.status-dot` child
- **File:** `packages/frontend/src/animations/agent-animations.ts:14-16`
- **Function:** `createSpin(element)`
- **Detail:** If the element has no `.status-dot` child, the function returns `undefined` instead of an anime.js instance. This breaks the documented contract that all animation functions return anime instances so callers can `.pause()`, `.restart()`, or chain `.then()`.

- **`scripts/pinyx-stub.mjs`** — The entire file is a mock LLM gateway for Docker Compose development. Returns hardcoded model list and chat completions. Documented in README as a stub.
- **`Dockerfile.pinyx-stub`** — Builds the above stub.
- **`auth.ts` no-op hook** (`routes/auth.ts:5-7`) — Empty auth hook when no API key is configured is intentional for dev mode.
- **`code-context.ts` empty fallbacks** (`routes/code-context.ts:14-33`) — Return empty data structures when no repo is configured; these are guard clauses, not stubs.
