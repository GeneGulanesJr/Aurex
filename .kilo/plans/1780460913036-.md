# Plan: Bumblebee Supply-Chain Scanner Dashboard Integration

## Summary

Integrate [perplexityai/bumblebee](https://github.com/perplexityai/bumblebee) — a Go CLI that scans developer endpoints for on-disk package/extension metadata and flags known supply-chain compromises — into the Aurex mission control dashboard. The backend will execute bumblebee scans, parse NDJSON output, persist results in LaPis, and stream findings to the frontend. The frontend will display findings in a new collapsible panel within the active mission view.

## Architecture

```
bumblebee CLI (Go binary on host)
      │ NDJSON (stdout)
      ▼
Backend: BumblebeeRunner  ──parse──▶  LaPis (scan results)
      │                                  │
      ├── REST routes                    │
      └── EventBus ──▶ WebSocket ──▶ Frontend: SupplyChainPanel
```

## Phase 2: Backend (`packages/backend`)

### 2.1 New client: `src/clients/bumblebee-client.ts`

- `scan(root: string, options)`: Spawns `bumblebee scan --profile <profile>` as a child process via `child_process.spawn`
- Parses NDJSON stdout line-by-line into `BumblebeePackage[]` and `BumblebeeFinding[]`
- Emits progress events via a callback interface
- Validates `bumblebee` binary is available (checks `BUMBLEBEE_BIN` env var or `PATH`)
- Handles timeouts, process errors, and graceful cancellation

### 2.2 New service: `src/orchestrator/bumblebee-runner.ts`

- Orchestrates a scan lifecycle:
  1. Creates scan record in LaPis
  2. Resolves scan root (mission repo workspace or `REPO_ROOT`)
  3. Invokes `bumblebee-client.scan()`
  4. Streams findings to EventBus as `scan_finding` events
  5. On completion: persists all packages/findings to LaPis, emits `scan_completed`
  6. On failure: emits `scan_failed` with error details
- Auto-trigger option: run a scan post-milestone when `autoScan: true` in mission config

### 2.3 New REST routes: `src/routes/bumblebee.ts`

| Method | Path | Purpose |
|--------|------|---------|
| `POST` | `/api/missions/:missionId/scans` | Trigger a scan for a mission |
| `GET` | `/api/missions/:missionId/scans` | List scan history for a mission |
| `GET` | `/api/missions/:missionId/scans/:scanId` | Get scan results (findings + summary) |
| `POST` | `/api/bumblebee/catalog` | Upload/update exposure catalog |
| `GET` | `/api/bumblebee/catalog` | Get current exposure catalog |
| `GET` | `/api/bumblebee/status` | Check if bumblebee binary is available |

### 2.4 LaPis integration

New LaPis client methods for:
- `POST /scans` — Create scan record
- `GET /scans/:id` — Get scan record with summary
- `GET /scans?missionId=X` — List scans for mission
- `PATCH /scans/:id` — Update scan status/summary
- `POST /scans/:id/packages` — Batch insert packages
- `POST /scans/:id/findings` — Batch insert findings
- `GET /scans/:id/findings` — Get findings for scan

### 2.5 Register routes in `server.ts`

Add bumblebee routes alongside existing mission/checkpoint/github/pinyx routes.

## Phase 4: Integration with Mission Lifecycle (Optional Enhancement)

### Auto-scan post-milestone

In `milestone-loop.ts`, after a milestone passes validation:
1. Trigger a `project` profile scan against the worktree
2. If findings are detected, emit an `escalation` event with trigger kind `unclassifiable_error` and context `{ supplyChainFindings: [...] }`
3. This surfaces compromised dependencies as a checkpoint requiring human review

### Exposure catalog management

Store catalog JSON in LaPis settings (`GET/PUT /settings/bumblebee_catalog`). The bumblebee runner passes it via `--exposure-catalog` flag.

## Prerequisites

1. **Go 1.25+** must be available on the host/container
2. **bumblebee binary** installed (`go install github.com/perplexityai/bumblebee/cmd/bumblebee@latest`)
3. **BUMBLEBEE_BIN** env var (optional, defaults to `bumblebee` on PATH)

---

## Persistence Strategy: LaPis Settings KV Store

Scan results are stored as JSON blobs via the existing `GET/PUT /settings/:key` endpoints in LaPis. No new LaPis schema is needed.

| Key | Value | Description |
|-----|-------|-------------|
| `bumblebee_catalog` | `ExposureCatalog` JSON | Current exposure catalog |
| `bumblebee_scan:<scanId>` | `BumblebeeScanResult & { findings: BumblebeeFinding[] }` | Individual scan with findings |
| `bumblebee_scans:<missionId>` | `{ scanIds: string[] }` | Scan history index per mission |

Benefits: zero LaPis changes, works with existing infrastructure, easy to inspect/debug.
