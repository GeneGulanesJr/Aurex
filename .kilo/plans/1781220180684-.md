# Auth0 Integration Plan — Google/Gmail Login

## Summary

Integrate Auth0 as the authentication provider with Google/Gmail as the sole social connection. Auth0 replaces the existing static `API_KEY` bearer auth. Users must log in before accessing any UI. Backend validates JWTs from Auth0 on every request.

**Decisions:**
- Auth0 **replaces** the existing `API_KEY` auth entirely
- Login **gates the entire app** — unauthenticated users see a login screen
- Auth0 config via **environment variables**
- User profile is **JWT-only (stateless)** — decoded from the token on each request, no LaPis storage
- Google/Gmail **only** as the social provider

### 2c. Add `useAuth0` Hook Wrapper (`hooks/useAuth.ts`)

Thin wrapper around `@auth0/auth0-react`'s `useAuth0` that also provides:
- `getToken()`: calls `getAccessTokenSilently()` for use in API/WS calls
- `user`, `isAuthenticated`, `isLoading`, `loginWithRedirect`, `logout`

### 2d. Auth Gate Component (`frame/LoginScreen.tsx`)

A full-page login screen matching the Aurex design system (dark bg, AUREX logo, "SIGN IN WITH GOOGLE" button). Shown when `!isAuthenticated && !isLoading`.

### 2e. Update `App.tsx`

- Import `useAuth` hook
- If `!isAuthenticated && !isLoading` → render `<LoginScreen />` instead of the dashboard
- Remove `API_KEY` usage from WebSocket options
- Pass `getToken` to API layer for Authorization headers

### 2f. Update API Layer (`api.ts`)

Replace `authHeaders()` which currently reads `VITE_AUREX_API_KEY`:
```ts
async function authHeaders(): Promise<HeadersInit> {
  const { getToken } = useAuth(); // can't use hook here
}
```

Since `api.ts` is not a React component, we need a different approach. Create a module-level token getter:

```ts
let _getToken: (() => Promise<string>) | null = null;

export function setTokenGetter(fn: () => Promise<string>) {
  _getToken = fn;
}

async function authHeaders(): Promise<HeadersInit> {
  if (!_getToken) return {};
  const token = await _getToken();
  return { Authorization: `Bearer ${token}` };
}
```

In `App.tsx`, after auth loads, call `setTokenGetter(getToken)` from the `useAuth` hook.

Change `apiFetch` to be async-aware for the token:
```ts
async function apiFetch(url: string, opts?: RequestInit): Promise<Response> {
  const headers = await authHeaders();
  return fetch(url, { ...opts, headers: { ...headers, ...opts?.headers } });
}
```

### 2g. Update WebSocket Auth (`hooks/useWebSocket.ts`)

Replace `apiKey` with async token getter:
- On `ws.onopen`, call `getToken()` and send `ws.send(JSON.stringify({ type: "auth", token: jwtToken }))`
- The backend will validate the JWT instead of comparing to a static API key

## 3. Backend Changes (`packages/backend`)

### 3a. Install `jose` (JWT/JWKS verification)

Lightweight, zero-dependency JWT library. Add to `packages/backend/package.json`.

### 3b. Update Config (`config.ts`)

Add Auth0 fields to `AppConfig`:
```ts
auth0Domain: string;
auth0Audience: string;
auth0ClientId: string;
```

Read from `AUTH0_DOMAIN`, `AUTH0_AUDIENCE`, `AUTH0_CLIENT_ID`.

### 3c. JWT Verification Middleware (`routes/auth.ts`)

Replace `createAuthHook(apiKey)` with JWT verification:

```ts
import { jwtVerify, createRemoteJWKSet } from "jose";

// Create JWKS client (cached)
let jwks: ReturnType<typeof createRemoteJWKSet> | null = null;

function getJWKS(domain: string) {
  if (!jwks) {
    jwks = createRemoteJWKSet(new URL(`https://${domain}/.well-known/jwks.json`));
  }
  return jwks;
}

export function createAuthHook(auth0Domain: string, auth0Audience: string, auth0ClientId: string) {
  return async (request: FastifyRequest, reply: FastifyReply) => {
    // Skip auth for health, WS upgrade (WS auth handled via message), and callbacks
    if (request.url === "/health" || request.url.startsWith("/ws") || request.url.startsWith("/api/github/callback")) return;

    const header = request.headers.authorization;
    if (!header || !header.startsWith("Bearer ")) {
      return reply.status(401).send({ error: "Missing Authorization header" });
    }

    const token = header.slice(7);
    try {
      const { payload } = await jwtVerify(token, getJWKS(auth0Domain), {
        issuer: `https://${auth0Domain}/`,
        audience: auth0Audience,
      });
      // Attach user info to request for downstream use
      request.user = {
        sub: payload.sub,
        email: payload.email,
        name: payload.name,
        picture: payload.picture,
      };
    } catch {
      return reply.status(401).send({ error: "Invalid or expired token" });
    }
  };
}
```

## 4. Full Removal of API_KEY Auth

Auth0 **completely replaces** the static `API_KEY` mechanism:

- **Remove** `API_KEY` env var from `.env.example` and `docker-compose.yml`
- **Remove** `VITE_AUREX_API_KEY` references from frontend
- **Remove** `apiKey` field from `AppConfig` in `config.ts`
- **Remove** `apiKey` option from `useWebSocket` and its `UseWebSocketOptions` type
- **Remove** static bearer token comparison in `auth.ts` (replaced by JWT/JWKS)
- **Remove** `apiKey` prop from `App.tsx` WebSocket usage

## 8. Auth0 Tenant Setup (Documented, Not Code)

The following needs to be configured in the Auth0 dashboard:
1. Create a new Application (Single Page App)
2. Add Google social connection (enabled only for Gmail)
3. Set "Allowed Callback URLs": `http://localhost:8080`
4. Set "Allowed Logout URLs": `http://localhost:8080`
5. Create an API with identifier matching `AUTH0_AUDIENCE`
6. Enable "Allow Offline Access" if refresh tokens are desired later
