# Plan: Docker Compose E2E Integration Test

## Goal
Create an automated E2E test that spins up the full Aurex stack in Docker Compose (real LaPis, PiNyx stub, backend, frontend) and validates all containers build, start, communicate, and serve correct responses.

## Design Decisions
- **Real LaPis**: Clone from GitHub (`GeneGulanesJr/LaPis`), build and run as a Docker service
- **PiNyx stub**: Tiny Node.js HTTP server mimicking the 2 endpoints the backend needs (`GET /v1/models`, `GET /health`). Building real PiNyx would require the Rust toolchain — a stub is more CI-friendly and sufficient for testing Aurex's infrastructure
- **Test runner**: Bash script with curl assertions and a `jq` dependency for JSON parsing
- **Compose file**: Separate `docker-compose.e2e.yml` (extends the production compose with lapis + pinyx-stub services)
- **Cleanup**: Script traps EXIT to always `docker compose down -v`

---

## Architecture

```
docker-compose.e2e.yml
├── lapis         (Node.js, :9100)  — cloned from GitHub, runs `lapis serve`
├── pinyx-stub    (Node.js, :7331)  — minimal stub responding to /v1/models + /health
├── backend       (Fastify, :3000)  — depends_on lapis + pinyx-stub (healthy)
└── frontend      (nginx, :80)      — depends_on backend (healthy)
```

## Step 1: Create `docker-compose.e2e.yml`

**New file**: `docker-compose.e2e.yml`

```yaml
services:
  lapis:
    build:
      context: .
      dockerfile: Dockerfile.lapis
    ports:
      - "9100:9100"
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://localhost:9100/health').then(r=>r.json()).then(j=>{if(j.status!=='ok')throw 1})"]
      interval: 5s
      timeout: 3s
      retries: 10
      start_period: 15s

  pinyx-stub:
    build:
      context: .
      dockerfile: Dockerfile.pinyx-stub
    ports:
      - "7331:7331"
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://localhost:7331/health').then(r=>r.json()).then(j=>{if(j.status!=='ok')throw 1})"]
      interval: 5s
      timeout: 3s
      retries: 5

  backend:
    build:
      context: .
      dockerfile: packages/backend/Dockerfile
    ports:
      - "3000:3000"
    environment:
      - LAPIS_ENDPOINT=http://lapis:9100
      - PINYX_ENDPOINT=http://pinyx-stub:7331
      - REPO_ROOT=/workspace
      - GIT_MAIN_BRANCH=main
    volumes:
      - ${REPO_ROOT:-/tmp}:/workspace
    depends_on:
      lapis:
        condition: service_healthy
      pinyx-stub:
        condition: service_healthy
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:3000/health"]
      interval: 5s
      timeout: 3s
      retries: 10
      start_period: 15s

  frontend:
    build:
      context: .
      dockerfile: packages/frontend/Dockerfile
    ports:
      - "8080:80"
    depends_on:
      backend:
        condition: service_healthy
```

Key differences from production `docker-compose.yml`:
- Uses `environment` instead of `env_file` (no `.env` file needed)
- Points to internal Docker network URLs (`http://lapis:9100`, `http://pinyx-stub:7331`)
- Adds `lapis` and `pinyx-stub` services
- Faster healthcheck intervals (5s vs 30s) for test speed
- Frontend maps port 80→8080 (avoid conflicts with anything on 80)

## Step 2: Create `Dockerfile.lapis`

**New file**: `Dockerfile.lapis`

Multi-stage Dockerfile that:
1. Clones the LaPis repo from GitHub (`GeneGulanesJr/LaPis`)
2. Installs dependencies
3. Runs `node src/http/server.js` (or `npx lapis serve --port 9100` — depends on the LaPis package structure)

```dockerfile
FROM node:22-slim
RUN apt-get update && apt-get install -y git && rm -rf /var/lib/apt/lists/*
WORKDIR /app
RUN git clone https://github.com/GeneGulanesJr/LaPis.git .
RUN npm install
EXPOSE 9100
CMD ["node", "src/http/server.js"]
```

Note: The exact CMD will need to be verified against the LaPis repo structure. The `smoke-lapis.js` script says `lapis serve --port 9100` which suggests a CLI entry point.

## Step 4: Create `scripts/pinyx-stub.mjs`

**New file**: `scripts/pinyx-stub.mjs`

Minimal HTTP server that responds to:
- `GET /health` → `{ "status": "ok" }`
- `GET /v1/models` → `{ "object": "list", "data": [{ "id": "test-model", "object": "model", "owned_by": "stub" }] }`
- `POST /v1/chat/completions` → OpenAI-compatible stub response with usage data

This is ~40 lines of Node.js using the built-in `http` module (zero dependencies).

## Step 5: Create `scripts/e2e-docker.sh`

**New file**: `scripts/e2e-docker.sh`

Bash script that:

1. **Prerequisites check**: Verify `docker`, `docker compose`, `curl`, `jq` are installed
2. **Start stack**: `docker compose -f docker-compose.e2e.yml up --build -d`
3. **Wait for healthy**: Poll `docker inspect` for all 4 services to report `healthy`
4. **Run assertions** (via curl against the frontend's nginx proxy at `:8080`):
   - Frontend serves HTML: `curl :8080/` returns 200 + HTML content
   - Backend health (via nginx proxy): `curl :8080/health` returns `{ "status": "ok" }` (lapis + pinyx stub both healthy)
   - Create mission: `POST :8080/api/missions` returns 201 + missionId
   - Get active missions: `GET :8080/api/missions/active` returns 200
   - Get mission by ID: `GET :8080/api/missions/:id` returns 200
   - WebSocket upgrade: `curl -i -N -H "Connection: Upgrade" -H "Upgrade: websocket" :8080/ws` returns 101
   - Backend health directly: `curl :3000/health` returns 200
   - LaPis health directly: `curl :9100/health` returns `{ "status": "ok", "db": true }`
   - PiNyx stub health directly: `curl :7331/health` returns `{ "status": "ok" }`
5. **Report results**: Print passed/failed counts, exit 1 on any failure
6. **Cleanup**: Trap EXIT to `docker compose -f docker-compose.e2e.yml down -v`

## Execution Order

1. `scripts/pinyx-stub.mjs` — no dependencies
2. `Dockerfile.pinyx-stub` — depends on stub
3. `Dockerfile.lapis` — depends on knowing LaPis repo structure
4. `docker-compose.e2e.yml` — depends on all Dockerfiles
5. `scripts/e2e-docker.sh` — depends on compose file
6. `package.json` — add script entry
7. Run `bash scripts/e2e-docker.sh` and iterate

## Risks & Mitigations

- **LaPis repo structure unknown**: The exact startup command for LaPis may differ from assumed `node src/http/server.js`. Will verify during implementation and adjust the Dockerfile.
- **Docker BuildKit / build times**: First run clones and builds everything (~2-3 min). Subsequent runs use cached layers.
- **Port conflicts**: E2E uses 8080 (frontend), 3000 (backend), 9100 (lapis), 7331 (pinyx-stub). Script checks ports are free before starting.
- **No git in cloud sandbox**: Docker builds happen inside Docker, not the host. The LaPis clone happens in the Dockerfile (git is installed in the build stage).
