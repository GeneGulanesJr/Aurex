# Plan: Multi-Mission Support

## Goal
Replace the single-mission `MissionRunner` with a `MissionRunnerPool` that supports N concurrent missions (configurable, default 3), with a queue for overflow. Add a sidebar mission list to the frontend.

## Design Decisions
- **Concurrency model**: Concurrent with configurable limit (`MAX_CONCURRENT_MISSIONS`, default 3)
- **Frontend**: Sidebar mission list with status badges; click to switch dashboard view
- **WS events**: Broadcast all events (no server-side filtering); frontend filters by `missionId`
- **Backward compat**: `GET /api/missions/current` returns the most recently started mission

## Step 2: Create `MissionRunnerPool`

**New file**: `packages/backend/src/orchestrator/mission-runner-pool.ts`

```typescript
interface PoolMissionStatus {
  missionId: string;
  state: "queued" | "planning" | "executing" | "waiting_checkpoint" | "completed" | "failed";
  queuePosition?: number;
}

interface MissionRunnerPool {
  submit(missionId: string): void;           // Start immediately or queue
  abort(missionId: string): void;            // Abort specific mission, free slot
  getStatus(missionId: string): PoolMissionStatus | null;
  getActiveMissions(): PoolMissionStatus[];  // All running + queued
  waitForCompletion(missionId: string): Promise<void>;
}
```

Implementation:
- Internal `Map<string, { runner: MissionRunner; state: PoolMissionStatus["state"] }>` for running missions
- Internal `string[]` queue for waiting missions
- `maxConcurrent: number` config
- On mission completion/failure: check queue, start next queued mission
- Each slot creates its own `MissionRunner` instance (already stateless per-run)
- Emit WS events: `mission_queued`, `mission_started`, `mission_completed` via EventBus

## Step 5: Update REST API routes

**File**: `packages/backend/src/routes/missions.ts`

Current routes:
- `POST /api/missions` — change `runner.start(missionId)` to `pool.submit(missionId)`
- `GET /api/missions/current` — return most recently started active mission (backward compat)

New routes:
- `GET /api/missions/active` — return `pool.getActiveMissions()` (running + queued with positions)
- `POST /api/missions/:id/abort` — call `pool.abort(missionId)`

The `runner` injection changes to `pool: MissionRunnerPool`.
