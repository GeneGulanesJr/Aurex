# LaPis Codebase Review #2: Post-PR #156 Follow-up

## Overview

This is a **second review** of the [LaPis](https://github.com/GeneGulanesJr/LaPis) codebase after PR #156 (`fix/code-review-improper-wiring`) was created. The first review identified 13 issues; PR #156 fixed them. This review checks the PR for regressions and finds remaining issues.

**Previous issues fixed by PR #156:** Issues #1–#13 from the first review are all addressed.

---

## HIGH Issues (Regressions from PR #156)

### R1. `services/dream.js` `dream()` no longer provides `sqlRaw` fallback — VACUUM/FTS silently skipped

**File:** `services/dream.js:10-12` (changed in PR #156)

**Old code:**

```js
const { sqlJson, sqlRun, sqlRaw, jsonErrNoExit } = require('../db');
function dream(deps) {
  return compactionDomain.dream({ ...deps, sqlRaw: deps.sqlRaw || sqlRaw });
}
```

**New code:**

```js
const { createStorageContext } = require('../src/platform/storage');
function dream(deps) {
  return compactionDomain.dream(deps);
}
```

**Problem:** `compactionDomain.dream()` calls `runCompact(deps)` which destructures `{ sqlRun, sqlRaw }` and calls `sqlRaw('VACUUM;')`. The caller `commands/session.js` only passes `{ sqlJson, sqlRun, softDeleteObservation }` — no `sqlRaw`. The `TypeError` is silently caught, so VACUUM and FTS optimization are **silently skipped** every time `dream()` runs. The `report.ok` is still set `true` unconditionally, masking the failure.

**Fix:** Add `sqlRaw` fallback in `services/dream.js`:

```js
function dream(deps) {
  const ctx = deps || createStorageContext();
  return compactionDomain.dream({ ...ctx, ...deps });
}
```

### R2. `createWithDeps()` added to `src/doc-index/index.js` but never imported — dead code

**File:** `src/doc-index/index.js:36-53` (added in PR #156)

**Problem:** The `createWithDeps(deps)` function was added to enable repository injection, but nothing in the codebase calls it. `grep -rn "createWithDeps"` only finds the definition and export.

**Fix:** Either wire it into a consumer (e.g., `src/cli/commands/docs.js`) or remove it.

## MEDIUM Issues

### R3. `test/storage-repositories.test.js` assertion will fail — missing `aurex` key (pre-existing)

**File:** `test/storage-repositories.test.js:22-29`

**Problem:** Test expects 6 repository keys but `createRepositories()` returns 7 (including `aurex`). The sorted actual output is `['analytics', 'aurex', 'codeIndex', 'docIndex', 'memory', 'trustSync', 'workflow']` but the test expects `['analytics', 'codeIndex', 'docIndex', 'memory', 'trustSync', 'workflow']`.

**Note:** Pre-existing issue (not introduced by PR #156), but PR #156 did not fix it either.

**Fix:** Add `'aurex'` to the expected array in the test.

## LOW Issues

### R4. `test/memory-domain.test.js` missing `recovery` in `expectedModules`

**File:** `test/memory-domain.test.js:10` (affected by PR #156)

**Problem:** `src/memory-domain/index.js` now includes `recovery: require('./recovery')`, but the test's `expectedModules` array doesn't list `'recovery'`. Test still passes (only checks listed modules are defined, not exhaustiveness), but test coverage for the recovery barrel export is missing.

**Fix:** Add `'recovery'` to the `expectedModules` array.

### R5. `test/services-dream.test.js` masks `sqlRaw` failure

**File:** `test/services-dream.test.js:66-70`

**Problem:** Test provides no `sqlRaw` in deps but asserts `result.ok === true`. This passes only because `dream()` sets `report.ok = true` unconditionally. The compact phase actually fails silently (`result.phases.compact.ok === false`).

**Fix:** Add `sqlRaw: vi.fn()` to the test deps and/or assert on `result.phases.compact.ok`.
