# Plan: Quota System Enhancements — UI Toggle + Per-Provider Quota Tracking

## Overview

Enhance the existing 5-hour quota system with two capabilities:

1. **Frontend enable/disable toggle** — Move quota enabled state from env-var-only into a LaPis settings KV, making it fully toggleable from the QuotaPanel UI. The env var `QUOTA_ENABLED` becomes a boot default, not the only control.

2. **Per-provider quota tracking** — Each PiNyx provider (e.g. `kilo`, `zai`, a custom OpenAI key) can be independently marked as "quota tracked". LLM calls routed through quota-tracked providers count against the 5hr window. Calls through non-tracked (paid/unlimited) providers bypass quota entirely.

---

## Design Decisions

- **Storage**: All quota config in LaPis settings KV (no new DB tables)
  - `"quota_config"` — global quota settings (enabled, window/burn defaults, per-provider overrides)
  - `"quota_window"` — per-provider active window state (renamed to `"quota_windows"` — a map of `providerId → QuotaWindow`)
- **Env var `QUOTA_ENABLED`**: Used as the initial default on first boot. Once the user toggles in the UI, the LaPis setting takes precedence.
- **Provider detection**: The model ID prefix (e.g. `zai/glm-5`) tells us which provider is being used. The wrapper inspects `req.model` to determine the provider and looks up that provider's quota window.
- **Untracked providers**: Pass through with no quota check at all. No window is created or checked.
- **Separate windows per provider**: Each quota-tracked provider has its own independent 5hr window and burn timer. Provider A's exhaustion doesn't affect Provider B.

## Data Model Changes

### New: `QuotaConfig` (stored in LaPis as `"quota_config"`)

```ts
interface QuotaProviderQuotaConfig {
  enabled: boolean;              // whether this provider counts against quota
  windowDurationMs?: number;     // override global default (optional)
  burnDurationMs?: number;       // override global default (optional)
}

interface QuotaConfig {
  enabled: boolean;              // global quota on/off (set from UI)
  windowDurationMs: number;      // default: 5 * 60 * 60 * 1000
  burnDurationMs: number;        // default: 60 * 60 * 1000
  providers: Record<string, QuotaProviderQuotaConfig>;  // keyed by provider id
}
```

### Changed: `"quota_window"` → `"quota_windows"` (map)

Currently a single `QuotaWindow | null`. Changes to `Record<string, QuotaWindow>` — one window per provider.

### `QuotaWindow` — unchanged

```ts
interface QuotaWindow {
  windowStart: string;
  windowDurationMs: number;
  burnDurationMs: number;
  firstLLMCallAt: string | null;
  isActive: boolean;
  lastActiveAt: string | null;
}
```

## Backend Changes

### 1. `packages/backend/src/enforcement/quota-gate.ts` — MODIFY

Add a new function for resolving per-provider effective config:

```ts
export function getEffectiveProviderConfig(
  quotaConfig: QuotaConfig,
  providerId: string,
): { tracked: boolean; windowDurationMs: number; burnDurationMs: number }
```

Existing functions (`checkQuota`, `recordFirstLLMCall`, etc.) remain unchanged — they operate on a single `QuotaWindow` as before. The routing layer (wrapper) calls them per-provider.

### 2. `packages/backend/src/clients/pinyx-quota-wrapper.ts` — MODIFY

Change from a single-window check to per-provider:

```ts
export function createQuotaAwarePinyxClient(
  inner: PinyxClient,
  opts: {
    getQuotaConfig: () => Promise<QuotaConfig | null>;
    getQuotaWindows: () => Promise<Record<string, QuotaWindow>>;
    saveQuotaWindows: (w: Record<string, QuotaWindow>) => Promise<void>;
    getProviderNames: () => Promise<Record<string, string>>;
  }
): PinyxClient
```

The `enforceAndTrack(req: ChatRequest)` function:
1. Extract provider ID from `req.model` (split on `/`, take first segment)
2. Load `QuotaConfig` via `getQuotaConfig()`
3. If `!quotaConfig.enabled` → pass through (global toggle off)
4. Look up provider in `quotaConfig.providers[providerId]`
5. If not found or `!providerConfig.enabled` → pass through (untracked provider)
6. Load `quotaWindows[providerId]` (may be null — first call for this provider)
7. Run `checkQuota(window, now)` → if exhausted, throw `QuotaExhaustedError` with provider info
8. If window is null, create one using `createQuotaWindow()` with the provider's effective durations
9. If `firstLLMCallAt === null`, call `recordFirstLLMCall()`
10. Save updated windows

### 3. `packages/backend/src/routes/quota.ts` — MODIFY

**`GET /api/quota`** — Returns `QuotaStatusResponse` with per-provider status array:
- Load `quota_config` from LaPis
- Load `quota_windows` from LaPis
- Load `pinyx_config` from LaPis to get provider list
- For each provider: build `QuotaProviderStatus` using `checkQuota()` and `getQuotaStatusDisplay()`

**`POST /api/quota/config`** — NEW endpoint. Accepts `QuotaConfigUpdateRequest`:
- Merges partial updates into existing config
- Saves to `"quota_config"` in LaPis
- Returns updated full config
- This is how the frontend toggles enabled/disabled and sets per-provider tracking

**`POST /api/quota/prefire`** — MODIFY to accept `providerId` in body:
- If `providerId` specified, only prefires that provider's window
- If no `providerId`, prefires all tracked providers

**`POST /api/quota/reset`** — MODIFY to accept optional `providerId`:
- If specified, resets only that provider's window
- Otherwise resets all tracked provider windows

### 4. `packages/backend/src/config.ts` — MODIFY

Keep env vars as boot defaults:
```ts
quotaEnabled: process.env.QUOTA_ENABLED === "true",
quotaWindowDurationMs: envInt("QUOTA_WINDOW_HOURS", 5) * 60 * 60 * 1000,
quotaBurnDurationMs: envInt("QUOTA_BURN_HOURS", 1) * 60 * 60 * 1000,
```

These are used to seed the initial `QuotaConfig` in LaPis on first boot. After that, LaPis setting takes precedence.

### 5. `packages/backend/src/orchestrator/mission-runner.ts` — MODIFY

- `resolvePinyx()`: Always wrap with quota-aware client. The wrapper itself checks the config.
- Remove the `if (!config.quotaEnabled) return inner` short-circuit. The wrapper handles it internally by reading `QuotaConfig` from LaPis.

### 6. `packages/backend/src/routes/missions.ts` — MODIFY

The quota guard in `POST /api/missions`:
- Load `quota_config` from LaPis (instead of using `appConfig.quotaEnabled`)
- Check if any tracked provider has an active, non-exhausted window
- If all tracked providers are exhausted → 429
- The model hint in the request determines which provider to check

### 7. `packages/backend/src/server.ts` — MODIFY (minor)

- On startup: if `"quota_config"` doesn't exist in LaPis, seed it from env var defaults
