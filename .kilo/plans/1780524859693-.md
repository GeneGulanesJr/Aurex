# Plan: 5-Hour Coding Plan Quota System with Prefire Logic

## Overview

Implement a quota system that enforces a 5-hour coding window with configurable burn duration. The system tracks the wall-clock time from the first LLM call within a 5-hour window. When the burn duration is exhausted, running missions are paused (since the underlying LLM API quota is exhausted). A "prefire" mechanism allows users to start a window early so the quota resets exactly when they begin serious coding.

**Design Decisions (confirmed with user):**
- **Opt-in**: disabled by default (`QUOTA_ENABLED=false`)
- **Pause on exhaustion**: running missions pause at the next checkpoint; can't continue without API access
- **Timer trigger**: the first LLM call (`pinyx.chat()` or `pinyx.chatStream()`) starts the 5hr window timer
- **No window = unlimited**: if no window has been started, all requests pass

**Core Formula:**
- `P = N + B - W` where:
  - `P` = prefire time (when the 5hr window starts)
  - `N` = desired coding start time
  - `B` = burn duration (wall-clock time until quota exhaustion, e.g. 1hr)
  - `W` = quota window (5hrs)

**Example (6PM coding start, 1hr burn, 5hr window):**
- Prefire at 2:00 PM → starts the 5hr window (timer hasn't started yet, window boundary established)
- 6:00 PM: first LLM call → burn timer starts, 1hr of wall-clock coding available
- 7:00 PM: burn duration exhausted → missions paused
- 7:00 PM: 5hr window expires (2PM + 5hrs) → auto-reset, fresh quota
- 7:00–8:00 PM: second burn cycle with fresh quota
- Enables continuous 24hr coding by chaining prefire windows

---

## Architecture

### Storage: LaPis Settings KV

State persisted in LaPis via existing `getSetting`/`setSetting`:
- `"quota_window"` — serialized `QuotaWindow` object

No new database tables or migrations needed.

### Timer: PiNyx Client Wrapper

Wrap the `PinyxClient` to intercept `chat()` and `chatStream()` calls. The wrapper:
1. On first call within a window: records `firstLLMCallAt` (starts the burn timer)
2. Before each call: checks if quota is exhausted → throws `QuotaExhaustedError` if so
3. After each call: no-op (wall-clock tracking, not per-call)

## Backend Files to Create

### 1. `packages/backend/src/enforcement/quota-gate.ts` (NEW)

Pure functions following the enforcement module pattern.

**Exported functions:**

```ts
export interface QuotaCheckResult {
  ok: boolean;
  reason?: "quota_exhausted" | "window_expired";
  remainingBurnMs?: number;
  remainingWindowMs?: number;
  windowResetsAt?: string;
}

export function createQuotaWindow(opts: { windowDurationMs?: number; burnDurationMs?: number; now?: Date }): QuotaWindow
export function prefire(window: QuotaWindow | null, now: Date, opts?: { windowDurationMs?: number; burnDurationMs?: number }): QuotaWindow
export function recordFirstLLMCall(window: QuotaWindow, now: Date): QuotaWindow
export function checkQuota(window: QuotaWindow | null, now: Date): QuotaCheckResult
export function getQuotaStatusDisplay(window: QuotaWindow | null, now: Date): QuotaStatusResponse
export function calculatePrefireTime(desiredStart: Date, burnDurationMs: number, windowDurationMs: number): Date
export function resetWindow(window: QuotaWindow, now: Date): QuotaWindow
```

**Key logic in `checkQuota`:**
1. If `window` is null → `{ ok: true }` (unlimited)
2. If `window.firstLLMCallAt` is null → `{ ok: true }` (burn timer hasn't started)
3. If `now - windowStart >= windowDurationMs` → auto-reset: new window at `now`, `{ ok: true }`
4. If `now - firstLLMCallAt >= burnDurationMs` → `{ ok: false, reason: "quota_exhausted", remainingWindowMs, windowResetsAt }`
5. Otherwise → `{ ok: true, remainingBurnMs, remainingWindowMs }`

### 2. `packages/backend/src/clients/pinyx-quota-wrapper.ts` (NEW)

Wraps `PinyxClient` to enforce quota on LLM calls:

```ts
export class QuotaExhaustedError extends Error {
  constructor(public readonly windowResetsAt: string) {
    super("Quota exhausted");
  }
}

export function createQuotaAwarePinyxClient(
  inner: PinyxClient,
  opts: { getQuotaWindow: () => Promise<QuotaWindow | null>; saveQuotaWindow: (w: QuotaWindow) => Promise<void>; enabled: boolean }
): PinyxClient
```

The wrapper:
- `chat()` / `chatStream()`: 
  1. If `!opts.enabled` → delegate directly
  2. Load quota window, call `checkQuota(window, new Date())`
  3. If `!ok` → throw `QuotaExhaustedError`
  4. If `ok` and `window.firstLLMCallAt === null` → call `recordFirstLLMCall(window, new Date())`, save
  5. Delegate to inner client
  6. Return result

## Integration Flow

### Prefire Flow

```
User clicks "Prefire" in QuotaPanel (or enters desired coding time)
  → POST /api/quota/prefire { windowDurationMs: 5hr, burnDurationMs: 1hr }
  → prefire() creates new QuotaWindow { windowStart: now, firstLLMCallAt: null }
  → Save to LaPis settings key "quota_window"
  → Returns { windowStart, windowEnd, prefireAdvice }
  → UI shows: "Window active. First LLM call starts your 1hr timer."
```

### First LLM Call Flow

```
Mission is running → planner calls pinyx.chat()
  → quota wrapper intercepts
  → load QuotaWindow from LaPis
  → checkQuota(window, now) → ok (no firstLLMCallAt yet)
  → recordFirstLLMCall(window, now) → sets firstLLMCallAt
  → save QuotaWindow to LaPis
  → emit { type: "quota_update", ... }
  → delegate to inner pinyx.chat()
```

### Quota Exhaustion Flow

```
Agent calls pinyx.chat() at 7:00 PM (1hr after firstLLMCallAt)
  → quota wrapper intercepts
  → checkQuota(window, now) → { ok: false, reason: "quota_exhausted" }
  → throw QuotaExhaustedError(windowResetsAt)
  → agent catches error, milestone loop returns { status: "checkpoint_needed", trigger: "quota_exhausted" }
  → mission-runner creates checkpoint
  → mission pauses
  → eventBus emits { type: "quota_exhausted", windowResetsAt }
  → UI shows: "Quota exhausted. Window resets at 7:00 PM."
```

### Auto-Reset Flow

```
7:00 PM arrives (2PM prefire + 5hrs)
  → Next checkQuota() call detects window expired
  → Auto-reset: new window starts at now
  → If mission is paused at quota_exhausted checkpoint → auto-resolve checkpoint
  → Mission resumes with fresh quota
  → New first LLM call starts fresh burn timer
```

## Timing Example (from the user's spec)

| Time | Event | Quota State |
|------|-------|-------------|
| 2:00 PM | User hits prefire | Window starts: `{ windowStart: 2PM, firstLLMCallAt: null }` |
| 6:00 PM | User starts mission; planner calls `pinyx.chat()` | `firstLLMCallAt` set to 6PM, burn timer starts |
| 6:00–7:00 PM | Mission running, multiple LLM calls | Within burn duration (1hr), all calls pass |
| 7:00 PM | Next LLM call | `now - firstLLMCallAt >= 1hr` → `QuotaExhaustedError` |
| 7:00 PM | Mission pauses at checkpoint | Trigger: `"quota_exhausted"` |
| 7:00 PM | Window expires (2PM + 5hrs) | Auto-reset on next check |
| 7:00 PM | Checkpoint auto-resolved | Mission resumes with fresh window |
| 7:00–8:00 PM | Second burn cycle | Fresh `firstLLMCallAt`, another 1hr of coding |
| 12:00 AM | Second window expires (7PM + 5hrs) | Next reset |
