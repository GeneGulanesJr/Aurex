# Issue #161: Hint unclear "Use `memory-code` for structured analysis."

## Problem

When the agent uses `bash` commands like `grep`/`rg`/`find` or `read` on code files in a **non-indexed** repo, a passive nudge is shown to the **user** via `ctx.ui.notify()`:

> 💡 Use `memory-code` for structured analysis. Index this repo first: `memory-code index-repo`

Problems:
1. The user sees a vague hint they can't act on directly
2. The agent doesn't see the nudge (it's a UI notification, not agent context), so it does nothing
3. The nudge keeps appearing uselessly (up to 8 times per session)
4. When the user copy-pastes the hint back to the agent, it awkwardly reads the skill file before acting

## Root Cause

`tool-guardrails.ts` uses `ctx.ui.notify()` (user-facing notification) for non-indexed repos, but the agent can't act on user notifications.

## Solution: Block + Auto-index

When the agent tries `grep`/`find`/`read` on a non-indexed repo:
1. **Block** the tool call (so the agent sees the reason)
2. **Auto-index** the repo by calling `memStreaming('code', { mode: 'index-repo', ... })` directly
3. Return a block reason telling the agent the repo has been indexed and to use `memory-code` going forward

This eliminates the vague user-facing nudge entirely and ensures repos get indexed automatically on first code access.

### Expected Flow

```
Agent: bash grep "pattern" src/
Guardrail: blocks → auto-indexes repo → returns reason:
  "This project was not indexed. It has been indexed (N files, M symbols).
   Use memory-code modes instead of raw grep/find:
   • memory-code search --repo <name> --query <query>
   • ..."
Agent: uses memory-code search --repo <name> --query "pattern"
```

### Change 2 — Add auto-index helper function (`tool-guardrails.ts`)

Add a deduplicating helper that tracks in-progress indexing to prevent concurrent indexing attempts:

```typescript
let activeIndexing: Promise<string | null> | null = null;

async function ensureIndexed(
  deps: GuardrailsDeps,
  resolvedCwd: string,
  projectName: string,
): Promise<string | null> {
  if (activeIndexing) {
    return activeIndexing;
  }
  activeIndexing = (async () => {
    try {
      const result = await deps.memStreaming(
        'code',
        { mode: 'index-repo', path: resolvedCwd, name: projectName },
      );
      deps.invalidateRepoCache();
      if (!result) return null;
      if (result.error) return `Indexing error: ${result.error}`;
      const summary = (result as any).summary || '';
      return summary;
    } catch (e) {
      return `Indexing failed: ${e instanceof Error ? e.message : String(e)}`;
    } finally {
      activeIndexing = null;
    }
  })();
  return activeIndexing;
}
```

## Risk

Medium. Key considerations:
- **Indexing time**: Large repos may take time. The `ensureIndexed` helper deduplicates concurrent triggers so only one indexing runs at a time. Subsequent blocked calls await the same promise.
- **Indexing failure**: If indexing fails, the block reason includes manual instructions as fallback. The agent won't be permanently stuck.
- **Piped commands / symbol lookups**: No exceptions for non-indexed repos — all grep/find are blocked until indexed. This is more aggressive but ensures consistent behavior.
- **Existing nudges removed**: The passive nudge counter is removed entirely since blocks replace them.
