# Fix Babel scope tracker warning for `RepoInfo` on first run

## Problem

When LaPis is first installed and `pi` is started for the first time, Babel emits a warning:

> The exported identifier "RepoInfo" is not declared in Babel's scope tracker as a JavaScript value binding

This happens because `extensions/memory-layer/host/project-detector.ts:1` imports `RepoInfo` (a TypeScript interface) mixed with runtime values:

```ts
import { REPO_CACHE_TTL, RepoInfo, state } from '../state';
```

Babel's `@babel/plugin-transform-typescript` treats the `import { RepoInfo }` as a value import. When line 5 re-exports it as `export { type RepoInfo }`, Babel's scope tracker has no record of it being declared as a type, so it warns. On subsequent runs the compiled output is cached, so the warning disappears.

## Fix

**File:** `extensions/memory-layer/host/project-detector.ts`

Change line 1 from:
```ts
import { REPO_CACHE_TTL, RepoInfo, state } from '../state';
```
to:
```ts
import { REPO_CACHE_TTL, type RepoInfo, state } from '../state';
```

This uses TypeScript's inline `type` import modifier, which tells Babel's scope tracker that `RepoInfo` is type-only and should be erased during compilation. The re-export on line 5 (`export { type RepoInfo }`) already uses the `type` keyword and is correct.

## Scope

- One line change in one file
- No behavioral changes
- Eliminates the first-run Babel warning
