# Plan: Fix Issues in PR #71 (Move Mission Creation to Main Area)

## PR Summary
Moves mission creation from 280px sidebar to full-width main content area as `MissionCreationView`. Sidebar becomes mission-list-only with a `+` button. Tabbed Create/Overview view when repo is prepared.

## Issues Found

### Issue 1: Dead `suggestedMission` state in App.tsx
**Severity: Medium (dead code)**

`App.tsx:113` declares `const [suggestedMission, setSuggestedMission] = useState<string | undefined>(undefined)`. This state is no longer consumed by any component — it was previously passed to `MissionSidebar → NewMissionForm → useNewMissionForm(onSubmit, suggestedDescription)`, but `MissionCreationView` now calls `useNewMissionForm(onSubmit)` without it.

`setSuggestedMission` is still called in the `onStartFromSuggestion` callback (line 309) and the auto-clear effect (lines 199-203) still processes it, but the value is never read.

**Fix:** Remove the `suggestedMission` state, the auto-clear effect, and the `setSuggestedMission` call from `onStartFromSuggestion`.

Files: `packages/frontend/src/App.tsx`

### Issue 2: `aurex:focus-new-mission` event fires before MissionCreationView mounts
**Severity: Medium (functional bug — form state stuck at `open: false`)**

In `App.tsx:211-212`:
```ts
selectMission(null);
window.dispatchEvent(new CustomEvent("aurex:focus-new-mission"));
```

`selectMission(null)` triggers a React state update, then the event fires synchronously. React 18 batches state updates, so `MissionCreationView` hasn't mounted yet when the event fires — the event listener isn't attached and the event is lost.

Impact: `form.open()` is never called. The form's `open` state stays `false`. While `canSubmit` doesn't depend on `open` (so submit still works), `SUBMIT_SUCCESS` resets to `initialFormState` with `open: false`, and the form's conceptual state is inconsistent. The `autoFocus` on the textarea compensates for focus.

**Fix:** Remove the `window.dispatchEvent` from `onNewMission`. Instead, have `MissionCreationView` call `form.open()` on mount via a `useEffect([], ...)` so the form is always in `open: true` state when rendered.

Files: `packages/frontend/src/App.tsx`, `packages/frontend/src/active/MissionCreationView.tsx`

### Issue 3: `preparedRepo` passed as `undefined` but typed as `null`
**Severity: Low (type inaccuracy)**

In `StatusBoard.tsx:64`:
```tsx
preparedRepo={preparedRepo ? { ... } : undefined}
```

`MissionCreationViewProps` types `preparedRepo` as `... | null`, but the actual value passed is `undefined`. Both are falsy so no runtime issue, but it's a type lie.

**Fix:** Change the ternary to pass `null` instead of `undefined`.

Files: `packages/frontend/src/passive/StatusBoard.tsx`

### Issue 4: Silent no-op in `onSubmit` wrapper
**Severity: Low (fragile but works in practice)**

In `StatusBoard.tsx:63`:
```tsx
onSubmit={async (description, cloneUrl) => { if (onExampleClick) await onExampleClick(description, cloneUrl); }}
```

If `onExampleClick` is ever not provided, clicking "Create Mission" silently does nothing. In practice it's always `handleCreateMission`, but this adapter is fragile.

**Fix:** Use a non-null assertion or make the contract explicit.

Files: `packages/frontend/src/passive/StatusBoard.tsx`

### Issue 5 (Non-issue, verified OK)
- `canSubmit` does NOT depend on `state.open` — confirmed by reading `useNewMissionForm.ts:110`: `canSubmit: state.description.trim().length > 0 && !state.submitting`
- Total cost footer IS preserved in `MissionSidebar.tsx` (confirmed at end of file)
- No dangling imports of deleted `EmptyState.tsx` or `NewMissionForm.tsx`
- `useMissions` reducer handles `null` in SELECT action correctly
